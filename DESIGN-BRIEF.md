# Design brief — govoss-catalog

The reference for the design system **as implemented**: what it is, why each part is the way
it is, and what will break if you change it carelessly. Read it before touching the UI.

**Live:** https://govoss-catalog.vercel.app · **Repo:** https://github.com/sarapis/govoss-catalog
· **MCP:** https://govoss-mcp.devin-31f.workers.dev

> **Rewritten 2026-08-14.** The previous version described the Civic Tech Field Guide design
> system, which govoss left on 2026-08-13. Every count, token and chrome description below is
> measured against the current build. For the CTFG relationship as it was — including three
> defects we reported and CTFG fixed in its v2.0.0 — see `UPSTREAM-CTFG.md` and
> `CTFG-CONTRAST-REPORT.md`, which are **historical record, not guidance**.

## What this is

A union catalogue of **government open source software** — **2,753 active entries** (plus 453
set aside and flagged, 3,206 rows in all) harvested first-hand from **17** national, municipal
and international government catalogues across **15** countries, normalised onto one schema,
translated, categorised, de-duplicated and liveness-monitored. It regenerates, republishes and
commits itself every Monday, unattended.

**Two audiences.** People in government procurement asking *"what can we stop paying for?"* —
`/products.html` lists **372 proprietary products, 290 of them with an open source
alternative**. And **AI agents**: the first consumer of this catalogue probed eight dead API
paths and then drove a headless browser at it, which is why an entire page and an MCP server
exist to give them a better route.

**Published by Sarapis.** CTFG remains a consumer of this catalogue's data; it is no longer
the brand, and nothing in the chrome says otherwise. **Do not reintroduce NYC identity
either** — the readership is European public-sector staff and the catalogue's credibility
rests on reading as neutral.

## Still true: you cannot edit the HTML

There are no `.html` source files. All four pages are generated by Python, and `site/*.html`
is build output overwritten every Monday.

| surface | path | built by | size |
|---|---|---|---|
| Catalog | `/` | `build_ui.py` (271) + `_ui_template.py` (534) | 1,834 KB |
| Proprietary software | `/products.html` | `build_products.py` (349) | 224 KB |
| Sources **and build status** | `/sources.html` | `build_sources.py` (459) | 91 KB |
| API + MCP | `/api.html` | `build_api.py` (324) | 62 KB |
| Shared chrome | all four | `theme.py` (632) | — |

`build_status.py` is **retired**; the status page merged into `/sources.html`, and
`/status.html` 308s there. **`/status.json` is still written** — it is a published endpoint
agents read.

### The brace rule, and the escape from it

`theme.py`, `_ui_template.py` and the `build_*.py` page templates hold CSS, markup and JS as
**plain strings with `__PLACEHOLDER__` tokens**, substituted explicitly at the end. No brace
doubling — which was the single most common way these files broke — and the substitution pass
**asserts no placeholder survived**, so a typo fails the build instead of rendering
`__N_ENTRIES__` to a reader. Keep it that way: if you need a value interpolated, use
`.replace()` or `%s`, never an f-string.

## The design system

**`@wegovnyc/design-tokens` v0.7.0**, commit `f5c95ad`, under the **`govoss` brand variant** —
the same system wegov.nyc and unnyc.wegov.nyc share. **Vendored, not transcribed:**
`vendor/wegovnyc/` holds `core.css` (the reference palette plus ~90 `--wg-*` semantics) and
`variant-govoss.css` (govoss's remap), and `theme.py` inlines them at build time.

Not vendored: the other products' variants, `index.css` (loads every variant; govoss renders
exactly one) and the Node token lint. `vendor/wegovnyc/README.md` has the full table.

**Why vendored rather than an npm dependency:** govoss has no bundler — it is Python emitting
static HTML, so there is nothing to install the package *into*. The version stamp is what makes
"which release is this?" answerable. **The tradeoff is real: an upstream fix does not reach
govoss until someone copies it here.** To take a change, copy the files, update the version and
commit in the README, and **re-run the contrast audit**.

⚠ The version lives in `vendor/wegovnyc/README.md` and `theme.tokens_version()` parses it. That
is weaker than the CTFG set it replaced, where every file stamped a version and all four
agreeing *was* the check: this is an assertion by whoever copied the files, not a property of
the copy. The runtime check that survives regardless is `--wg-brand-id`.

### `theme.py` is an ALIAS LAYER, and that is a deliberate divergence

wegov.nyc and UNNYC migrated every rule to read `--wg-*` directly and deleted their alias
layers, for a good reason: **an alias carrying its own VALUE is unreachable by the variant
system.** govoss keeps aliases, but **none of them carries a value** — every one resolves to a
`--wg-*` semantic, so a variant remap still propagates, which is the property that rule
protects. What it buys is not touching ~250 `var(--x)` call sites spread across Python template
strings, where a missed one fails silently.

### ⚠ The mapping is by ROLE and MEASURED CONTRAST, never by name

This is the part that will bite you. Two family semantics **cannot** be used where their names
suggest, because govoss uses those roles for text:

Recomputed 2026-08-14 from the vendored CSS against the page ground `#FBFBFB`:

| family token | value | measured | why govoss cannot use it by name |
|---|---|---|---|
| `--wg-text-muted` | `#8A96A8` | **2.90:1** | govoss's tertiary tier is used **24×** as text |
| `--wg-accent` | `#4B92DB` | **3.15:1** | govoss's `--primary` is used **26×**, including links |
| `--wg-accent-soft` | `#7BB4E8` | **2.13:1** | a mid blue; govoss uses that role as a *pale ground* behind accent text |

Mapping the first two naively would have broken the contrast floor in **50 places**. All three
are fine as fills and non-text marks; they are simply not text colours here. `--primary`
therefore takes `--wg-accent-strong` (**5.13:1**), and `--primary-tint` takes
`--wg-surface-band`, the family's actual tinted-ground token.

⚠ Two figures previously recorded for these were slightly optimistic — `--wg-accent` as 3.26
and `--wg-text-muted` as 3.00. The real values are *worse*, so the decision they justify is
sound, but recompute rather than copy. `--wg-accent-soft` is quoted as **2.41:1** in
`theme.py`; that was measured on the products toggle's own ground, not the page ground, and
both are correct in context.

The three text tiers, outgoing → incoming, all verified passing:

```
primary     17.4  -> 13.15   --wg-text            #162e51  (navy rather than near-black)
secondary    8.20 ->  8.69   --wg-brand-light     #2c4a73
tertiary     5.17 ->  5.31   --wg-text-secondary  #5A6A82  (slightly BETTER)
```

**`--ink-400` remains NON-TEXT ONLY**, mapped to `--wg-border`, exactly as upstream had it. If
you type `var(--ink-400)` on something with words in it, that is the bug.

**Shadows changed and it is intentional.** The hard-offset `2px 2px 0` was the CTFG signature
and went with it; the family's is a soft ramp. This is the single most visible difference on
the page.

### The brand variant must be APPLIED, not merely present

`theme.assert_variant_live()` runs on every build and checks the **root tag**. This system has
already shipped a dead variant once — on wegov.nyc, two theme files existed, were never
imported and never applied, so every semantic silently resolved to the wrong brand's values for
months (KI `wegovnyc-design-system`).

govoss would fail differently and more visibly: `variant-govoss.css` is what remaps
`--wg-font-display` to the self-hosted Space Grotesk, so an unapplied variant falls back to the
family's `DM Serif Display` — a face this repo deliberately does not ship — and the page
silently renders in Georgia.

⚠ **The first version of that assert was broken.** It substring-searched the whole page for
`data-brand="govoss"`, and the vendored variant file's own comment contains that literal, which
is inlined into every page — so it **could only ever pass**. Caught by deleting the attribute
and watching the build succeed. **Test a guard adversarially**, by breaking the thing it checks.

## Fonts are self-hosted, not CDN

The design system names families and ships no `@font-face`; its siblings load them from
`fonts.googleapis.com`. That is unusable here for two independent reasons: the pages are
self-contained by rule, **and the readership is European public-sector staff, for whom a Google
Fonts request is a live GDPR objection** (German courts have found against it). So the woff2s
are in `fonts/`, served same-origin, copied to `site/fonts/` by `build_site.sh`. Upstream now
records this as a sanctioned divergence.

**9 files, 308 KB** — but `unicode-range` means a typical reader fetches only the ~**108 KB**
latin set.

Subsets follow what the catalogue actually contains: latin + latin-ext for the European
sources; **Cyrillic for Inter alone**, because Inter carries the descriptions and the Bulgarian
entries need it; no Vietnamese or Greek, since no source produces them. CJK is in none of them,
so Taiwan's Chinese names fall back to the system face — correct, as no webfont covers CJK at a
sane size.

**Marcellus is declared at weight 400 alone.** It is single-weight, and the shared `400 700`
rule would let the browser synthesise a fake bold. It sets exactly one word — the Sarapis
wordmark — and matches `next.sarapis.org`'s `--sds-font-logo`. The OFL requires the licence
travel with the fonts: `fonts/OFL-*.txt` ship too, do not drop them to save bytes.

## The chrome, and the network request that no longer happens

**There is none.** The build makes **no network request at all**. That is a property worth
protecting: a weekly unattended run can no longer be affected by a third party's CMS being slow
or down.

What was removed on 2026-08-13, by owner decision:

- The **CTFG utility bar** and its CMS-fed link row. `utility_bar()` survives as a function and
  returns **only the skip link** — that is an accessibility affordance, not chrome, and it must
  stay the first focusable element. It takes and ignores a `nav` argument so the four builders
  keep one call shape.
- The **CTFG mark** in the topbar. The lockup is now the govoss wordmark and its subtitle in
  live type, so it matches the page's own Space Grotesk and stays selectable and searchable.
- The **four CMS-fed footer columns**. Replaced by govoss's own material — the catalogue, the
  data endpoints, the project — which is what a reader of *this* page wants anyway.
- **`ctfg_nav.py`**, deleted.

**Topbar:** wordmark · Catalog / Sources / API · a *Submit a catalog* button.
**`/products.html` is deliberately NOT in the top nav** — it is a way *into* the open source,
not a peer of it, and a nav item would misstate what this catalogue is.

**Footer:** three columns, then the **real Sarapis lockup** pulled from `next.sarapis.org` —
`/sarapis-mark.png` at 36px beside the word in Marcellus, uppercase, `.05em`, weight 400. It is
not redrawn.

**No CC BY-NC-SA badge.** The original handoff paired one with "data CC BY 4.0". Shipping that
image would tell a scanning reader the data is NonCommercial — the opposite of what the repo
grants, and a deterrent to exactly the reuse this exists for. Terms are stated in words, each
scoped to what it covers.

## Components, as built

**Catalog** — hero with pill search · **agent banner** · 6 stat tiles · wrapping-flex body with
sticky sidebar facets and results · toolbar · entry rows · submit block.

**Sidebar facets are three groups**, not the old 51-chip wall: **Function** (19), **Replaces**
(most-replaceable first) and **Source catalog** (17). Top 6 each with a "Show all N"
disclosure, a live "narrow the filters" input that filters *labels, not results*, and
`aria-pressed` on every option. **There is no Country facet** — country rides on the source
label instead, since every source belongs to exactly one country.

**Toolbar** — three pill selects (sort, licence, repository state) plus two toggles: *Replaces
a paid product* and *Include 453 set-aside entries*.

**Stamps are three tiers** — six pill types used to sit at one weight, so a licence and "this
repository no longer exists" read identically:

| tier | items | treatment |
|---|---|---|
| Loud endorsement | In N catalogs | mint fill, deep-green text |
| Loud warning | Repo gone · Archived upstream | ink fill, paper text, alert icon |
| Quiet metadata | licence · Wikidata QID | **no pill at all** — the grey meta line |

**A "Recommended" seal was a fourth stamp. It was retired 2026-08-14** — not for visual reasons
but because it could not state a single honest claim. `recommended_for_gov` was set by two
sources on different grounds: SILL asserts it (that catalogue *is* France's recommended-software
list, 668 rows), while Munich's 85 came from `recommended_for_gov = not built` — Munich's own
claim is *"in production use at the City of Munich"*, which is **adoption**, and the flag
inverted it, so software Munich actually built got no seal. AngularJS carried *Recommended* and
*Archived upstream* side by side.

The field is untouched in the data and still exported as `recommended_for_government` on 683
rows; only the pill is gone. Rationale sits with the code in `build_ui.py`. **If you reinstate
any endorsement stamp, split the two provenances first** — this is the case
`wikidata_via: comptoir:<how>` exists to prevent, and there is no `recommended_via`.

**Products** — one dense table of 372 products with description, function, alternatives and a
link into the filtered catalogue. Products with and without an alternative are the same kind of
object, so they share a table and *has a govoss alternative* is a filter over it, on by
default. Cards are **static HTML**, so deep links (`#p-dropbox`) work natively and an agent
reading raw HTML gets the content.

**Sources** — hero with a published stamp · tiles · 17 catalogue rows with sparklines · open
items · weekly diff and last-run steps · surveyed-and-rejected cards.

**API** — 5 endpoint cards with **measured** sizes · a real entry that parses as JSON · field
rules · the MCP server config and 5 tools · etiquette · citation.

## Do not change

- **The four agent affordances.** An HTML comment above `<title>` listing the endpoints; three
  `<link rel="alternate">` plus the meta description; the visible "don't scrape this page"
  banner **directly above the stat tiles**, early in the DOM; and the endpoint paths themselves.
- **`/status.json`.** Retiring the page was a design decision; retiring the endpoint would
  break agents.
- **Entry semantics.** `licence` is null rather than guessed; `entry_url` is null rather than
  constructed; `repo gone` needs two consecutive failed checks. The UI must never paper over a
  missing value with a plausible one — the catalogue's credibility rests on this.
- **The set-aside toggle.** Those entries are flagged, never deleted, and each keeps its reason.
- **Light-only.** The approved designs are light-only and the DS tokens are light-only already,
  so the dark branches are gone rather than half-maintained. Because of that `body` **must**
  paint its own background from a token — a transparent body borrows the host's ground and
  renders dark text on dark.

## Seven rules paid for in bugs

Every one shipped, was found on the rendered page, and is now a rule. They are
design-system-independent — none of them changed when the tokens did.

1. **A native `<select>` ignores your CSS until `appearance: none`.** Three toolbar selects
   rendered as OS controls beside pill buttons. The CSS was applied and had no effect —
   `getComputedStyle` would have reported the radius. Removing the appearance also removes the
   arrow, so the chevron is an inline SVG data URI with its colour **baked**, because a data URI
   cannot read a CSS variable.
2. **A `<select>` sizes to its widest option.** The licence list made one 472px wide, which
   scrolled the whole page sideways on a phone. Cap the width.
3. **A flex item defaults to `min-width: auto`** and refuses to shrink below its content, so
   `overflow-x` alone cannot contain it. `min-width: 0` first, then overflow.
4. **Never use a percentage height against an auto-height parent.** The topbar rendered 522px
   tall instead of 88px once the mobile query applied. `min-height` + flex centring instead.
5. **Prose is not a chip row.** `.legal` was `display:flex` with a gap, so every text node and
   link became a flex item — punctuation detached and "MIT" wrapped onto its own line.
6. **A truthfully-proportional bar can render as nothing.** Eight of ten step bars were 0px,
   because a sub-second step against a 12-minute harvest is 0%. Known durations floor at 3%; an
   unrecorded one gets a dashed track, so "fast" and "not measured" stay distinguishable.
7. **Fixed-height strips must not wrap.** Text wrapped to three lines inside a 36px bar and was
   clipped.

Rules 3 and 7 were both found on the CTFG utility bar, which no longer exists. The lessons
generalise to any fixed-height flex strip; the evidence does not, which is worth knowing if you
go looking for the markup.

*(Two further rules in the previous version — `--ink-400` at 2.44:1 and white on mid green at
2.65:1 — were properties of the CTFG palette. Their successors are the measured-contrast
mapping table above, which is where that lesson now lives.)*

## Accessibility

**WCAG 2.1 AA re-audited 2026-08-13** after the design-system move, by sweeping **every text
node on all four pages** plus pressed and toggled states: **zero failures, lowest ratio
4.9:1** on accent-over-tint chips.

The previous 5.17:1 was a property of the CTFG palette, not a requirement. 4.9 clears AA's 4.5
with margin, and chasing 5.17 by darkening every accent chip would cost the accent identity for
no accessibility gain.

The move surfaced one genuine failure and three tight spots, all fixed:

- The **pressed toggle was 2.41:1** — `--wg-accent-soft` is a mid blue where govoss uses that
  role as a pale ground. Pressed states now use navy text.
- Three **10–11px badges** sat at 4.62–4.9 on mid green or tint; now on the dark tone.

⚠ **The first sweep missed the 2.41 entirely because no facet was pressed.** Audit interactive
states explicitly, not just the page at rest.

Also in place: `lang="en"`, a `<main>` landmark, a skip link (there are ~45 tab stops before
the first result — the facet sidebar alone is ~30 buttons), unbroken heading order,
`aria-hidden` on decorative icons, and reflow passing at 320px.

**One skip link per page, and it is the first focusable element — verified on all four.**
`/products.html` carried **two** until 2026-08-14: `theme.utility_bar()` emits one, and that
page also had its own hardcoded copy, so the tab order held two identical *Skip to content*
links and a screen reader announced the target twice. Left over from the 08-13 chrome removal,
when `utility_bar()` shrank to just the skip link and this page's copy stopped being the only
one. Emit it from `utility_bar()` only.

**No screen-reader testing has been done.** Do not read the audit as a conformance claim.
VoiceOver/NVDA is the honest next step, and `/products.html` — a large table — is the surface
most likely to expose problems.

## Previewing, shipping, verifying

```bash
pip install -r requirements.txt
python3 build_ui.py && python3 build_sources.py && python3 build_api.py && python3 build_products.py && bash build_site.sh
open site/index.html
```

**Do not run `bash run.sh` to preview** — it is 16 steps and ~20 minutes of harvest against
fourteen governments' infrastructure, and it deploys, commits and pushes at the end. For a real
URL without touching production, `cd site && vercel deploy --yes` gives a preview; add `--prod`
only when you mean it.

`run.sh` deploys and commits automatically at the end of every successful run, gated on every
earlier step exiting 0. Merge to `main` and Monday publishes it.

**Verification, in the order that actually works:**

- **Measure the DOM, don't trust a screenshot.** The browser pane in this workflow returns
  blank and stale frames repeatedly; `getBoundingClientRect` and `getComputedStyle` were right
  every time. Every bug above was confirmed by measurement.
- **Rebuild `site/` before testing it.** One "failure" was `build_site.sh` not having been
  re-run.
- **But measurement cannot see everything.** The native-select bug passed every structural
  check — correct classes, correct computed radius, no console errors — and was caught by a
  human looking at the page. Some defects only have eyes as a detector.
- **After a deploy, wait before testing.** Two Worker tests and one Vercel test in this project
  reported failures that were really the previous version still being served.
- There is no visual regression test. Check the rendered page, not that the patch applied.

## Where govoss diverges from `@wegovnyc/design-tokens`

Three divergences, all deliberate, all recorded so a future "resync" does not quietly undo
them:

| # | the family does | govoss does | why |
|---|---|---|---|
| 1 | consumers read `--wg-*` directly, no aliases | keeps a **value-free alias layer** | ~250 `var()` call sites live inside Python template strings, where a missed one fails silently. No alias carries a value, so variant remaps still propagate. |
| 2 | loads fonts from a CDN | **self-hosts 9 woff2** same-origin | a Google Fonts request is a live GDPR objection for European public-sector readers. Sanctioned upstream. |
| 3 | `--wg-font-display` is DM Serif Display | `variant-govoss.css` remaps it to **Space Grotesk** | that face is not vendored here; adding one is an asset decision, not a token decision. |

**Do not "resync" govoss with a newer release without re-running the contrast audit.** The
role-mapping table above is the load-bearing part: a sync that took the family's names at face
value would reintroduce contrast failures in ~50 places and would look like a tidy-up.

## Open, and deliberately not done

- **Screen-reader testing has never run.** See *Accessibility*. Highest-value open item here.
- **`vendor/wegovnyc/README.md` claims govoss's guard is "the contrast assert in `theme.py`".**
  There isn't one — `assert_variant_live()` is the only build-time guard, and contrast is swept
  manually. Either write the assert or correct the README.
- **The get-involved block is duplicated** in `_ui_template.py` and `build_sources.py`. It has
  already caused one bug where a fix to one left the other stale.
- **The sparklines fill in over time.** Runs before 2026-08-12 have no per-catalogue record, so
  they render as grey "not recorded" bars rather than invented history.
- **`get_stats` on the MCP server can be up to an hour stale** — a 1-hour edge cache on
  `meta.json`. Fine for weekly data, but the tool an agent polls to detect a rebuild lags.
- **The Sarapis mark is a PNG at 117×116** displayed at 36px. An SVG would be sharper if one
  exists.
