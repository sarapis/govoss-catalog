# Design brief — govoss-catalog

**The restyle described in the first version of this file is built and live.** This is now the
reference for the design system as implemented: what it is, why each part is the way it is,
and what will break if you change it carelessly. Read it before touching the UI.

**Live:** https://govoss-catalog.vercel.app · **Repo:** https://github.com/sarapis/govoss-catalog
· **MCP:** https://govoss-mcp.devin-31f.workers.dev

---

## What this is

A union catalogue of **government open source software** — 3,080 entries harvested first-hand
from 17 national, municipal and international government catalogues across 15 countries,
normalised onto one schema, translated, categorised, de-duplicated and liveness-monitored. It
regenerates, republishes and commits itself every Monday, unattended.

**Two audiences.** People in government procurement asking *"what can we stop paying for?"* —
165 proprietary products are mapped to open source alternatives. And **AI agents**: the first
consumer of this catalogue probed eight dead API paths and then drove a headless browser at
it, which is why an entire page and an MCP server exist to give them a better route.

**Published by Sarapis, in affiliation with the Civic Tech Field Guide.** Not a CTFG property —
that distinction is deliberate and shows up in the chrome.

---

## Still true: you cannot edit the HTML

There are no `.html` source files. All three pages are generated by Python, and `site/*.html`
is build output overwritten every Monday.

| surface | path | built by | size |
|---|---|---|---|
| Catalog | `/` | `build_ui.py` (196) + `_ui_template.py` (465) | 1,882 KB |
| Sources + build status | `/sources.html` | `build_sources.py` (457) | 71 KB |
| API + MCP | `/api.html` | `build_api.py` (317) | 41 KB |
| Shared chrome | all three | `theme.py` (454) | — |

`build_status.py` is **retired**; the status page merged into `/sources.html`. `/status.html`
308s there. **`/status.json` is still written** — it is a published endpoint agents read.

### The brace rule, and the escape from it

The builders hold markup in f-strings, so a literal `{` or `}` must be doubled. **But all the
CSS, markup and JS now live in `theme.py` and `_ui_template.py` as PLAIN strings with
`__PLACEHOLDER__` tokens**, substituted explicitly at the end. No brace doubling, and the
substitution pass asserts no placeholder survived — a typo fails the build instead of
rendering `__N_ENTRIES__` to a reader. Keep it that way: if you need a value interpolated, use
`.replace()` or `%s`, never an f-string.

## The design system

Civic Tech Field Guide tokens. `theme.py` holds every colour, font, radius and shadow **once**
— three builders read it, so they cannot drift. Do not invent values outside these.

```
--paper-50  #FBFBFB  page ground        --violet-500 #574FD9  primary, links, stat numbers
--paper-100 #F1F1F1  tinted, row hover  --violet-700 #1F1A73  hover, hard pill shadow
--white     #FFFFFF  cards, bars        --violet-100 #F1F0FF  active-facet wash
--ink-900   #19191E  primary text       --green-500  #01B583  endorsements, PASS
--ink-600   #4D4D4A  secondary text     --green-700  #006348  text on mint, green shadow
--ink-400   #9FA4A3  tertiary / meta    --mint-300   #67F5C2  "in N catalogs" stamp
--line-300  #CDCDCB  border             --mint-100   #EAFFF9  pale wash
--line-200  #ECECEC  row divider        --shadow-ink #181818  hard bar shadow
```

**Type.** Space Grotesk (display), Archivo (uppercase labels + overlines, `.14em`), Inter
(body and dense data), system mono (paths, code), **Marcellus** (the Sarapis wordmark only).
Sentence case for headlines; UPPERCASE only for button labels and overlines.

**Shadows are hard offset, zero blur** — the CTFG signature: `2px 2px 0` in ink, violet or
green. **Dividers are 1px dashed ink** between sections. Radius: 5px chips, 10px blocks, 14px
cards, 20px stat tables, full pill on buttons, selects and search. Motion is 120ms on colour
and transform only.

**Light-only, by decision.** The previous build had three-state theming; the approved designs
are light-only, so the dark branches are gone rather than half-maintained. Because of that
`body` **must** paint its own background from a token — a transparent body borrows the host's
ground and renders dark text on dark.

## Fonts are vendored, not CDN

The CTFG design system loads Space Grotesk / Archivo / Inter from `fonts.googleapis.com`. That
is unusable here for two independent reasons: the pages are self-contained by rule, **and the
readership is European public-sector staff, for whom a Google Fonts request is a live GDPR
objection** (German courts have found against it). So the woff2s are in `fonts/`, served
same-origin, copied to `site/fonts/` by `build_site.sh`.

9 files, 344 KB total — but `unicode-range` means a typical reader fetches only the ~103 KB
latin set. **Verified on production: every request is same-origin, and 4 of 9 font files load.**

Subsets follow what the catalogue actually contains: latin + latin-ext for the European
sources; **Cyrillic for Inter alone**, because Inter carries the descriptions and 171 Bulgarian
entries are deliberately untranslated; no Vietnamese or Greek, since no source produces them.
CJK is in none of them, so Taiwan's 57 Chinese names fall back to the system face — correct, as
no webfont covers CJK at a sane size.

**Marcellus is declared at weight 400 alone.** It is single-weight; the shared `400 700` rule
would let the browser synthesise a fake bold. The OFL requires the licence travel with the
fonts — `fonts/OFL-*.txt` ship too, do not drop them to save bytes.

## The chrome is CMS-driven

The utility bar and the four footer link columns come from the Civic Tech Field Guide's own
Payload CMS: `https://cms.civictech.guide/api/navigation`, five documents keyed by `location`
(a Main Menu plus four `Footer — <group>`). When CTFG edits its menu, this follows on the next
weekly run.

Finding it required correcting two false leads, recorded so nobody repeats them:
`civictech.guide` is a Next.js front end with **no API**, and `app.civictech.guide` is
**Softr**, which answers 200 to *any* path — so `/api/globals/header` "existed" and did not.
The CMS is the separate `cms.civictech.guide` host.

**Fetched at build time, never in the browser.** A runtime call would put a third-party request
on every reader — the same objection that killed the font CDN — and would break the page when
the CMS is slow. `ctfg_nav.py` caches each success to `cache/ctfg_nav.json` and falls back to
that cache, then to a two-link floor. **A build must never publish an empty nav because someone
else had an outage**: an empty bar looks deliberate to a reader and signals nothing to us.

**Brand.** Topbar is the govoss wordmark + title, then the CTFG mark to its right — govoss to
the left of the mark, as the approved lockup has it. The mark is inlined SVG so it inherits
`currentColor` and costs no request; the govoss word is live type so it matches the page and
stays selectable. The footer carries the **real Sarapis lockup** pulled from `next.sarapis.org`
— `/sarapis-mark.png` at 36px beside the word in Marcellus, uppercase, `.05em`, weight 400,
exactly what that site's `.sds-logo` and `--sds-font-logo` specify. It is not redrawn.

**No CC BY-NC-SA badge.** The handoff paired one with "data CC BY 4.0". Shipping that image
would tell a scanning reader the data is NonCommercial — the opposite of what the repo grants,
and a deterrent to exactly the reuse this exists for. Terms are stated in words, each scoped to
what it covers.

## Components, as built

**Catalog** — hero with pill search · **agent banner** · 6 stat tiles · wrapping-flex body with
sticky sidebar facets and results · toolbar · entry rows · submit block.

**Sidebar facets replaced the 51-chip wall.** Three groups (19 functions, 15 countries, 17
source catalogues), top 6 each with a "Show all N" disclosure, a live "narrow the filters"
input that filters *labels not results*, and `aria-pressed` on every option.

**Stamps are three tiers** — the single most important change. Six pill types used to sit at
one weight, so a licence and "this repository no longer exists" read identically:

| tier | items | treatment |
|---|---|---|
| Loud endorsement | Recommended | green fill, white text, hard green shadow, seal icon |
| Loud endorsement | In N catalogs | mint fill, deep-green text, hard green shadow |
| Loud warning | Repo gone · Archived upstream | ink fill, paper text, alert icon |
| Quiet metadata | licence · Wikidata QID | **no pill at all** — the grey meta line |

**Toolbar** — three pill selects plus two toggles: "Replaces a paid product" (108 entries) and
"Include 102 set-aside entries".

**Sources** — hero with a published stamp · 5 tiles · 17 catalogue rows with 8-run sparklines ·
open items · weekly diff and last-run steps · 14 surveyed-and-rejected cards.

**API** — 5 endpoint cards with **measured** sizes · a real entry that parses as JSON · 7 field
rules · the MCP server config and 5 tools · etiquette · citation.

## Do not change

- **The four agent affordances.** An HTML comment above `<title>` listing the endpoints; three
  `<link rel="alternate">` plus the meta description; the visible "don't scrape this page"
  banner **directly above the stat tiles**, early in the DOM; and the endpoint paths themselves.
- **`/status.json`.** Retiring the page was a design decision; retiring the endpoint would
  break agents.
- **Entry semantics.** `licence` is null rather than guessed; `entry_url` is null rather than
  constructed; `repo gone` needs two consecutive failed checks. The UI must never paper over a
  missing value with a plausible one — the catalogue's credibility rests on this.
- **The set-aside toggle.** Those entries are flagged, never deleted, and each keeps its reason.

## Rules paid for in bugs

Every one of these shipped, was found on the rendered page, and is now a rule.

1. **A native `<select>` ignores your CSS until `appearance: none`.** Three toolbar selects
   rendered as OS controls beside pill buttons. The CSS was applied and had no effect —
   `getComputedStyle` would have reported the radius. Removing the appearance also removes the
   arrow, so the chevron is an inline SVG data URI, with its colour **baked** to `#4D4D4A`
   because a data URI cannot read a CSS variable.
2. **A `<select>` sizes to its widest option.** The licence list made one 472px wide, which
   scrolled the whole page sideways on a phone. Cap the width.
3. **A flex item defaults to `min-width: auto`** and refuses to shrink below its content, so
   `overflow-x` alone cannot contain it — the utility bar pushed the page instead of scrolling
   inside its strip. `min-width: 0` first, then overflow.
4. **Never use a percentage height against an auto-height parent.** The topbar rendered 522px
   tall instead of 88px once the mobile query applied. `min-height` + flex centring instead.
5. **Prose is not a chip row.** `.legal` was `display:flex` with a gap, so every text node and
   link became a flex item — punctuation detached and "MIT" wrapped onto its own line.
6. **A truthfully-proportional bar can render as nothing.** Eight of ten step bars were 0px,
   because a sub-second step against a 12-minute harvest is 0%. Known durations floor at 3%; an
   unrecorded one gets a dashed track, so "fast" and "not measured" stay distinguishable.
7. **Fixed-height strips must not wrap.** "Part of the" wrapped to three lines inside the 36px
   utility bar and was clipped.
8. **A palette token is not automatically a TEXT token.** `--ink-400` is a legitimate CTFG
   value and reads fine as a border, but at 2.44:1 it failed WCAG on every label, count and
   caption it was used for. Text colours now go through `--ink-faint` (ink-500, 5.17:1);
   `--ink-400` survives for non-text only. If you type `var(--ink-400)` on something with words
   in it, that is the bug.
9. **White on a mid-green is not accessible.** `#FFFFFF` on `--green-500` is 2.65:1 — it looked
   confident and failed badly. `--ink-900` on the same green is 6.62:1, so the fill and its
   hard shadow both survive.

## Previewing, shipping, verifying

```bash
pip install -r requirements.txt
python3 build_ui.py && python3 build_sources.py && python3 build_api.py && bash build_site.sh
open site/index.html
```

**Do not run `bash run.sh` to preview** — it is a ~20-minute harvest against fourteen
governments' infrastructure, and it deploys, commits and pushes at the end. To see a change on
a real URL without touching production, `cd site && vercel deploy --yes` gives a preview.

`run.sh` deploys and commits automatically at the end of every successful run, gated on all 15
steps exiting 0. Merge to `main` and Monday publishes it.

**Verification, in the order that actually works:**

- **Measure the DOM, don't trust a screenshot.** The browser pane in this workflow returned
  blank frames and odd scaling repeatedly; `getBoundingClientRect` and `getComputedStyle` were
  right every time. Every bug above was confirmed by measurement.
- **But measurement cannot see everything.** The native-select bug passed every structural
  check — correct classes, correct computed radius, no console errors — and was caught by a
  human looking at the page. Some defects only have eyes as a detector.
- **After a deploy, wait before testing.** Two Worker tests and one Vercel test in this project
  reported failures that were really the previous version still being served.
- There is no visual regression test. Check the rendered page, not that the patch applied.

## Where govoss diverges from the CTFG design system

**Three of the accessibility fixes are patches to the design system, applied here.** They are
recorded because a future regeneration from the DS bundle would silently revert them, and
because every other CTFG property inherits the same defects.

| # | DS says | Measured | govoss does instead |
|---|---|---|---|
| 1 | `tokens/colors.css:41` &mdash; `--ink-faint: var(--ink-400)` | **2.44:1** on `--paper-50`, 2.53:1 on white | `--ink-faint: var(--ink-500)` &mdash; 5.17:1 |
| 2 | `--verified: var(--green-500)`, spec'd with white text | **2.65:1** | `--ink-900` on the same green &mdash; 6.62:1 |
| 3 | icon set ships with **no `aria-hidden`** (0 occurrences in `_ds_bundle.js`) | n/a | every decorative icon gets `aria-hidden="true"` |

Number 1 is the important one: **the design system's own semantic alias for faint TEXT points
at a colour that cannot legally carry text.** It is a one-line fix upstream, and until it is
made, any CTFG property using `--ink-faint` on words is failing WCAG 1.4.3.

A fourth is arguable: the utility bar sets `--mint-300` on `--violet-500` (**4.37:1**, just
under). That pairing comes from the restyle spec rather than the DS's own CSS, so it may be
local &mdash; but if CTFG's real utility bar uses it, it is upstream too.

**These should go back through Claude Design rather than living here forever.** Until they do,
do not "resync" govoss with the DS bundle without re-checking contrast: the sync would look
like a tidy-up and would reintroduce three WCAG failures.

The other seven fixes are correctly local &mdash; `lang`, `<main>`, the skip link and heading
order are page structure, and the 320px reflow bug was our own markup, not a DS value.

## Open, and deliberately not done

- **Accessibility: WCAG 2.1 AA audited 2026-08-12. 10 issues found, all fixed.** Contrast now
  clears 4.5:1 on all three pages — **lowest measured anywhere is 5.17:1**. `lang="en"`, a
  `<main>` landmark and a skip link are in place, heading order is unbroken, icons are
  `aria-hidden`, and reflow passes at 320px. The suspicion previously recorded here was
  correct: `--ink-400` measured 2.44:1 and failed everywhere it carried words.
  **Not done: testing with a real screen reader.** This was automated checks plus keyboard
  navigation, which catches most issues but not all of them — VoiceOver/NVDA would be the next
  step, and no claim of full conformance should be made until it has run.
- **The utility bar shows one CTFG link**, not the full Main Menu set, if the CMS is
  unreachable at build time. Check `cache/ctfg_nav.json` is current if it looks thin.
- **The sparklines fill in over time.** Runs before 2026-08-12 have no per-catalogue record, so
  they render as grey "not recorded" bars rather than invented history.
- **`get_stats` on the MCP server can be up to an hour stale** — a 1-hour edge cache on
  `meta.json`. Fine for weekly data, but the tool an agent polls to detect a rebuild lags.
- **The Sarapis mark is a PNG at 117×116** displayed at 36px. An SVG would be sharper if one
  exists.
