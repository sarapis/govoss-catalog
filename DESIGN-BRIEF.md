# Design brief — govoss-catalog

A restyle brief for a designer picking this up cold. Paste-ready.

**Live:** https://govoss-catalog.vercel.app · **Repo:** https://github.com/sarapis/govoss-catalog
(MIT code / CC BY 4.0 data)

---

## What this is

A union catalogue of **government open source software** — 3,070 entries harvested first-hand
from 17 national, municipal and international catalogues (France, Italy, Germany, Denmark,
Bulgaria, Belgium, Sweden, Netherlands, Portugal, Canada, Taiwan, Finland, Ireland, the EU
institutions, and a global registry), normalised onto one schema, translated to English,
categorised by function, de-duplicated and liveness-monitored.

**Who reads it.** Two audiences, and the second one is unusual:

1. **People in government procurement and digital teams**, asking either *"what exists?"* or —
   the question the catalogue is really built for — *"what can we stop paying for?"* There is a
   `replaces` field mapping entries to proprietary products, so someone can start from an
   invoice line rather than a category.
2. **AI agents.** The first consumer of this catalogue probed eight dead API paths and then
   drove a headless browser at it. The page now tells agents *not* to scrape it, in four
   separate places. That is a real design constraint, covered below.

It regenerates and republishes itself every Monday, unattended.

---

## Read this first: you cannot edit the HTML

**There are no `.html` source files.** All three pages are generated by Python scripts that
hold the markup, CSS and JS inside f-string literals. `site/*.html` is build output and is
overwritten every Monday by the scheduled run.

| surface | live path | generated by | size |
|---|---|---|---|
| Catalogue (the main event) | `/` | `build_ui.py` (405 lines) | 1,823 KB |
| Sources + rejected survey | `/sources.html` | `build_sources.py` (164 lines) | 27 KB |
| Build status + changelog | `/status.html` | `build_status.py` (363 lines) | 17 KB |

**The f-string trap:** because the templates are f-strings, every literal `{` and `}` in CSS
and JS is **doubled** — `.item {{ padding: 1rem; }}`. Single braces are interpolation slots and
will either raise or silently swallow your rule. This is the single most common way to break
these files.

**The page is 1,823 KB but the design surface is only 24 KB.** 1,799 KB of it is the catalogue
data inlined as JSON in a `<script>`. So you have a lot of room for CSS, and effectively none
for per-row imagery — see Performance below.

## Hard constraints

Every one of these was earned by a bug. `CLAUDE.md` in the repo has the full account.

**1. Output is pure ASCII.** `build_ui.py` ends with
`.encode("ascii", "xmlcharrefreplace")`. Prose uses HTML entities (`&mdash;`), data is
`\uXXXX`-escaped. **Entities are NOT decoded inside `<script>`**, so a non-ASCII character in
JS must be a `\u` escape — a `·` separator in the JS once shipped as literal mojibake.
*Status: this began as a workaround for a host that could not declare a charset. The Vercel
deployment now serves `content-type: text/html; charset=utf-8`, so it is currently
belt-and-braces. Relaxing it is a legitimate proposal — just make it a deliberate decision
rather than an accident, and keep the `<script>` rule either way.*

**2. Self-contained, no build step.** One HTML file, inline `<style>` and `<script>`, no CDN,
no external stylesheet, no web font, no external images. There is no asset pipeline — anything
you add has to be copied into `site/` by `build_site.sh`. **System font stack only** today.
A web font is possible but is a pipeline change, not a CSS change; say so explicitly if you
want one.

**3. Never name a JS variable after an element `id`.** Browsers expose ids as globals. A
variable `showex` declared in one function and read in another silently resolved to the
checkbox *element* — always truthy — and the entry count denominator was permanently wrong
without throwing. Read `el('showex').checked` explicitly.

**4. The four agent-discoverability affordances must survive a redesign.** They are deliberate
and independently targeted:
   - an **HTML comment above `<title>`** listing the JSON endpoints, for agents reading raw HTML
   - `<link rel="alternate" type="application/json">` ×3 and a `<meta name="description">`
   - a **visible banner directly above the stat tiles** — "Building something? Don't scrape
     this page — there is a JSON API" — positioned early in the DOM so a text extraction hits
     it in the first screenful. **If you move it below the fold, it stops working.**
   - `/llms.txt`, `/robots.txt`, `/sitemap.xml` (generated elsewhere, not your concern)

**5. Three-state theming.** Light, dark, and system-default. Implemented as `:root` (light),
`@media (prefers-color-scheme: dark)`, and an explicit `[data-theme]` override. All three
branches must define every colour token — a token defined only inside a media query breaks the
other two states.

--dev      #1F4E8C / #7FA9E0

The palette is intentionally sober — this is a civic reference tool, not a product landing
page. Keep it credible to a procurement officer. That said, the current look is *undesigned*
rather than deliberately restrained, which is why you are here.

## Component inventory (the catalogue page)

Ordered as they appear. Class names in `build_ui.py`.

| component | class | notes |
|---|---|---|
| Header | `h1`, `.sub` | headline + lede. **Copy is wrong — see below.** |
| API banner | `.apibar` | the "don't scrape" notice. Must stay above the tiles. |
| Stat tiles | `.stats` / `.stat` | 8 tiles: entries, distinct repos, countries, with publiccode.yml, in English, functions, dead links, in 2+ catalogues |
| Controls | `.controls` | search `input[type=search]`, licence `<select>`, sort `<select>`, "show N filtered" checkbox, repo-state `<select>` |
| Filter chips | `.chips` / `.chip` | **three stacked rows** — 19 functions, 15 countries, 17 sources. Each chip carries a count and toggles via `aria-pressed`. This is the densest, ugliest part of the page and the best place to spend your effort. |
| Result count | `.count` | "N of M entries" |
| Entry list | `.list` / `.item` | 100 rows rendered at a time |
| ↳ country badge | `.cc` | two-letter code |
| ↳ title row | `.title` | name (linked to repo) + pills |
| ↳ pills | `.pill` + `.rec` `.dead` `.ex` `.multi` + status variants | licence, Wikidata QID, `recommended`, `repo gone`, `archived`, filter reason, "in N catalogues" |
| ↳ description | `.desc` | one line, may be machine-translated |
| ↳ footer | `.foot` / `.src` | source catalogue deep links, joined with `+` |
| Show more | `.more` | pagination button |
| Empty state | `.empty` | |
| Footer | `.foot` | |

**Pills are doing too much work.** A single row can carry six of them (status, recommended,
QID, licence, repo-state, filter-reason) plus two more in the footer. They are visually
undifferentiated, so a licence and a "this repo is gone" warning read at the same weight.
That is the clearest single design failure on the page.

## Copy that is factually wrong, and should be fixed in the restyle

Found while preparing this brief. All in `build_ui.py`, all user-visible:

- `<h1>` says **"European public-sector open source"** — the catalogue includes Taiwan, Canada
  and a global registry. Not European.
- The lede says **"Eight national catalogues"** — there are 17.
- `<title>` says "European public-sector open source — aggregated catalogue".
- `<meta name="description">` says "eight European national catalogues" — this is the SEO
  description and the one agents read.

The stat tiles directly above the lede say 3,070 entries and 15 countries, so the page
currently contradicts itself in the first screenful. Suggested framing: it is a **union
catalogue of government open source, worldwide**, whose distinguishing feature is that every
entry is harvested first-hand from a government's own catalogue.

## Do not change

- The four agent affordances (constraint 4), especially the banner's position.
- The JSON endpoint paths, or the redirects to them.
- **Entry semantics.** `licence` is `null` rather than guessed when the upstream string is not
  real SPDX; `entry_url` is null rather than constructed when a catalogue has no per-entry
  page; `repo gone` requires two consecutive failed checks. The UI must not paper over a
  missing value with a plausible-looking one — the catalogue's credibility rests on this.
- The `show N filtered` toggle. Filtered entries are **flagged, never deleted**, and each
  carries its reason. Hiding the reason would misrepresent the data.

## Previewing your work

```bash
pip install -r requirements.txt
python3 build_ui.py && bash build_site.sh    # ~5s, no network
open site/index.html
```

`build_status.py` and `build_sources.py` are the same shape. **Do not run `bash run.sh`** to
preview — it is a 25-minute harvest against fourteen governments' infrastructure, and it
deploys and commits at the end.

There is a `python3 test_detect_lang.py` regression test, but it covers data, not UI. **There
is no visual regression test — check the rendered page, not that the patch applied.**
String-replace edits against these f-strings have silently "succeeded" against the wrong file
before.

## Shipping

Do not deploy by hand. `run.sh` deploys and commits automatically at the end of every
successful run, gated on all prior steps passing. Merge to `main`; the Monday run publishes it.
If you need it live sooner, ask — there is a one-line manual deploy.

## Where judgment is genuinely wanted

1. **The three chip rows.** 51 chips stacked in three bands is the page's worst area. Faceted
   filtering over three independent dimensions, all of which matter. Progressive disclosure?
   A sidebar? Combined into one control?
2. **Pill hierarchy.** Six pill types at one visual weight (above). Which of these are
   *warnings* (repo gone, filtered) versus *metadata* (licence, QID) versus *endorsements*
   (recommended, in N catalogues)?
3. **Density.** 3,070 entries, 100 rendered at a time, one-line descriptions. Is a table the
   honest form here rather than cards? Who actually scans this, and for what?
4. **Mobile.** Currently untested and almost certainly poor.
5. **Accessibility.** Selects have `aria-label`, chips have `aria-pressed`, there is a
   `:focus-visible` outline — but it has never been audited. Contrast in particular: `--slate`
   on `--paper` is used for the descriptions, which is most of the page's text.
